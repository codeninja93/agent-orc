ASSUMPTION REVERSAL

33 IDEASOPERATION: INVERT14 LOAD-BEARING BELIEFS

Spec rests on 14 unexamined assumptions; flipping each is the fastest route to the design space Deep has not seen. Each plate below shows the belief that was struck out, and what stood up in its place.

REV·01 Human attention is free and interruptible at will ⇄

Interrupt budget: each subagent gets N human-interrupt tokens per feature, spending one reaches Deep directly — makes attention a priced resource instead of orchestrator whim.

REV·02 Questions are served first-come, first-answered ⇄

Escalation auction: blocked agents bid their interrupt budget, highest-value question surfaces first, Deep answers one question not a queue.

REV·03 The orchestrator's job is coordination ⇄

Name the orchestrator role precisely as The Interviewer — its real job is question compression, merging 5 subagent questions into 1 human question.

REV·04 Agents must message each other to collaborate ⇄

Blackboard architecture: no agent-to-agent messaging, but a shared append-only blackboard per worktree, any agent reads, only section owner writes.

REV·05 Report-upward means total mutual blindness ⇄

Read-only peering: agents may read each other outputs but may never ask each other anything — kills round-trips while preserving report-upward rule.

REV·06 Coordination overhead is invisible and untracked ⇄

Transcript tax: every orchestrator-relayed message logs its token cost to the dashboard so coordination overhead becomes a visible first-class metric.

REV·07 Domain ownership is enforced by written policy ⇄

Enforce domain ownership with capability tokens not policy — the jira credential exists in exactly one sandbox, so agents cannot disobey what they cannot reach.

REV·08 Every external integration deserves an agent ⇄

Tool-server subagents: jira / github / slack are not agents but MCP servers with a tiny LLM in front for intent translation — cheaper, deterministic, cacheable.

REV·09 Every call has to go through a model ⇄

Deterministic shim first: jira agent answers 80 percent of calls from a typed API with zero LLM tokens, escalating to a model only for fuzzy lookups.

REV·10 Ephemeral means destroyed on completion ⇄

Worktree hibernation instead of destruction: snapshot container plus db to a tarball, delete compute, resurrect instantly when the feature reopens.

REV·11 Cleanup should happen the instant work ends ⇄

Destroy on merge plus 24h post-mortem window so a bad merge can be inspected with its original environment still alive.

REV·12 Ephemeral resources means ephemeral evidence ⇄

Keep the artifact, kill the compute: worktree dies but the flight recorder (transcripts, diffs, decisions, costs) persists forever and is indexed for future retrieval.

REV·13 Agents specialize by verb — plan, execute, test ⇄

Codebase-region agents: agents own directories not verbs, so an auth agent accumulates real expertise in its region across many features.

REV·14 Specialization runs along one axis only ⇄

Verbs × regions matrix: role agents stay stateless, region agents are stateful memory-holders that role agents consult before acting.

REV·15 Every feature starts from a blank slate ⇄

The Historian subagent: only job is answering have-we-done-this-before from the flight-recorder index — cheap model, big retrieval index.

REV·16 Fewer tokens out is always cheaper ⇄

Minimal output is a false economy when it causes rework — measure tokens-per-merged-feature not tokens-per-call.

REV·17 Compression and brevity are the same thing ⇄

Structured output not short output: enforce a JSON schema per agent to get compression and machine-checkable handoffs simultaneously.

REV·18 Verbosity always costs money ⇄

Two-channel output: thin control channel (schema, enters orchestrator context) plus fat evidence channel (disk / dashboard, never enters context unless requested) — verbosity becomes free.

REV·19 Tokens are the scarce resource ⇄

Reframe the scarce resource as orchestrator context window not tokens — design for what the orchestrator must hold, let everything else be fat and on disk.

REV·20 One plan, one executor, one attempt ⇄

Speculative parallel execution: planner emits 3 plans, 3 executors run in 3 worktrees at once, verifier picks the winner — compute is cheap, Deep time is not.

REV·21 Tests are written after the code exists ⇄

Test-first inversion: tester runs FIRST and writes failing tests from the feature description, making executor definition-of-done mechanical and killing verify ambiguity.

REV·22 Work flows forward: spec → code → commit ⇄

Backward chaining from the commit: start by writing the commit message and PR description, work backwards to the diff required — forces intent clarity up front.

REV·23 Observability is a read-only window ⇄

Steerable dashboard: click any running agent to pause, inject a note, kill, or fork it — observability without control is just anxiety.

REV·24 The past is fixed once it has happened ⇄

Time-travel replay: scrub the timeline backward, change one decision, re-run from that point — the flight recorder makes this possible.

REV·25 The web app is the primary interface ⇄

Build the TUI first and the web app as a second renderer of the same event stream — Deep is a terminal multitasker, one event log two front-ends.

REV·26 Timelines are measured in elapsed time ⇄

Cost heat-map: color the timeline by dollars rather than duration to expose which agent is the money pit at a glance.

REV·27 When an agent is unsure, it asks the human ⇄

Answer-from-repo first: every clarifying question must be attempted against code, git history and past features before reaching Deep — track the deflection rate as a metric.

REV·28 An answer is consumed once and forgotten ⇄

Decision ledger: every answer Deep gives becomes a durable reusable project rule, checked before any agent asks again — answer once, never again.

REV·29 The system waits to be prompted ⇄

Ambient backlog: orchestrator watches jira, CI failures and flaky tests and proposes features to Deep rather than waiting to be prompted.

REV·30 Done means merged ⇄

Extend the pipeline past merge with deploy agent, canary watcher and auto-revert — done becomes a production metric not a git event.

REV·31 Resources are created fresh per feature ⇄

Resource pool with leases: pre-warmed postgres / redis containers leased to worktrees and wiped on return, killing per-feature cold-start cost.

REV·32 Each agent is pinned to one fixed model ⇄

Model ladder with automatic promotion: every subtask starts on the cheapest model and retries on a stronger one only on failed verification.

REV·33 Model assignment is hand-tuned forever ⇄

Escalation telemetry is a map of where cheap models fail, and it auto-tunes the default model assignment over time.

Git-as-the-message-bus: agents communicate by committing to the worktree, every handoff is a commit, the timeline IS git log — audit, replay and observability come free.

Git notes for agent metadata: attach reasoning, cost and decisions to commits via git notes so context travels with the repo and needs zero extra infra.

Event-sourced system state: state is a fold over the event log, agents are crash-safe, the dashboard is just a projection.

Hierarchy of orchestrators: a feature-orchestrator per worktree plus a meta-orchestrator across features as the thing Deep talks to — scales to N parallel features without context explosion.

Risk-tiered agents classified by blast radius (read-only, writes-code, writes-prod, spends-money) with different approval gates and sandbox strictness per tier.

Approval gates replace questions entirely: agents make assumptions, record them in an assumption log, Deep approves or rejects at gate points instead of answering a question queue.

MOR·09P05 human touchpoint

Async question inbox: questions accumulate and Deep batch-answers them like email — never interrupted, fits terminal multitasking.

MOR·10P07 model assignment

Task-complexity router: a tiny classifier scores file count, diff size and ambiguity, then routes to haiku / sonnet / opus per task instead of fixed per-agent models.

MOR·11P06 memory scope

Cross-repo global memory: patterns learned building product A are available when building product B — this is the actual leverage of one-system-many-products.

MOR·12P06 memory scope

Per-region memory files: every directory gets an auto-maintained AGENTS.md that agents update as they learn, so memory lives beside the code it describes.

MOR·13P10 verification

Two-tier verification economics: typecheck, lint and tests as gate 1 (free, deterministic), LLM review as gate 2 — never pay for gate 2 if gate 1 fails.

MOR·14P10 verification

Canary-as-final-verifier: for products with production traffic, the last verification step is real users not another model.

MOR·15P03 isolation unit

Three-tier isolation ladder chosen by risk classification: in-place edit for a typo, branch-only for small changes, full worktree plus container for real features.

MOR·16P02 specialization

Generalist model with tool-scoped personas: no separate agents at all, just one model with different system prompts and different tool grants — an agent is merely a capability profile.

MOR·17P14 state persistence

Agent as a pure function: stateless, takes a typed input file, emits a typed output file — fully resumable, unit-testable, and replayable.

MOR·18P01 topology

Deterministic workflow engine with LLM only at the leaves: the pipeline is code, not a model deciding what comes next — huge token savings and far higher reliability.

MOR·19P15 cost control

Dry-run mode: the whole pipeline executes against a mock executor to show the plan and a cost estimate before a single real dollar is spent.

MOR·20P10 verification

Shadow mode benchmarking: run the system against a feature Deep already built and diff its output against the real commit — earn trust empirically before delegating.

MOR·21P15 cost control

Cost-per-feature leaderboard: historical table of feature vs cost vs rework rate used to tune the system with evidence instead of intuition.

MOR·22P15 cost control

Dollar cap with graceful degradation: at 80 percent of budget the system downshifts every agent to the cheapest model and narrows scope rather than dying.

MOR·23P15 cost control

Wall-clock cap per feature forcing agents to report partial progress, preventing silent runaway.

MOR·24P11 failure handling

Step cap per agent as the cheapest possible infinite-loop guard.

MOR·25P04 resource lifecycle

Pooled warm containers plus snapshot-hibernate: worktree state snapshots into the pool on pause, eliminating cold-start on both provision and resume.

MOR·26P13 concurrency

N-plans-parallel then vote: three planners produce three plans, the orchestrator merges or picks, cost is trivial compared to executing the wrong plan.

▲model deprecationPRE·15

SWARM LOGIC

20 IDEASOPERATION: DECENTRALISENO MASTER PLAN

Forbidding the master plan exposes that most of the orchestrator's job is work ASSIGNMENT, which a shared queue plus local rules does for free — the orchestrator's real irreducible job is the human contract, not coordination.

SWM·01pheromone

Stigmergy via the filesystem: agents leave marks (failing tests, TODO files, lint errors) and other agents are attracted to them — a failing test IS the pheromone, no coordinator required.

SWM·02local rules

Three dumb local rules replace the assignment logic: fix a failing test you can fix, claim any work item matching your capability, write a note and die if you cannot progress in N steps.

SWM·03claiming

Claim-by-lockfile work distribution eliminates the assignment step entirely and makes concurrency safe with no central scheduler.

SWM·04allocation

Ant-colony task allocation with response thresholds: the longer a task waits and the more important it is, the more likely a lower-threshold agent picks it up — load balances itself.

SWM·05emergence

Emergent decomposition: rather than a planner breaking the feature down, spawn agents that each attempt the whole feature and abort where competence runs out, leaving a note — the breakdown is discovered not designed.

SWM·06selection

Evolutionary variant selection: N executors, brutal selection on test pass rate and diff size, then breed the survivor approach into the next round.

SWM·07quorum

Quorum sensing as a spec-drift defense: do not begin executing until 2 of 3 analysts independently converge on the same interpretation of the request.

SWM·08signalling

Waggle dance: an agent that found a productive approach broadcasts a compact how-I-did-it that other agents copy, giving cross-feature learning without designing a central memory.

SWM·09boundedness

Termite-mound bounded build: agents may only modify files adjacent to already-changed files, naturally constraining diff sprawl.

SWM·10extensibility

Capability-tagged work queue where agents pull what matches their profile — adding a new agent type is just adding a new puller, making the system trivially extensible.

SWM·11mortality

Death as a feature: agents are cheap and mortal, any agent exceeding its step budget dies and leaves its partial work as a pheromone for the next one — robustness through disposability.

SWM·12ingestion

In a swarm there is no jira agent, jira is simply another pheromone source polled into the shared work queue.

SWM·13telemetry

Local rules generate observability for free — the event log of claims, releases and deaths IS the timeline the dashboard renders.

SWM·14decay

Pheromone decay: stale work items lose priority and eventually expire, preventing a growing graveyard of half-finished tasks.

SWM·15recruitment

Recruitment instead of escalation: a stuck agent raises its pheromone to attract a stronger model rather than escalating up a chain of command — the model ladder as swarm recruitment.

SWM·16locality

No global state at all: everything an agent needs lives in the worktree it is standing in, giving portability and resumability for free.

SWM·17economy

Minimal viable swarm is radically cheaper to build than eight bespoke role agents — three rules, one shared queue, N identical workers differing only in tool grants.

SWM·18resilience

Anti-fragility architecture test: kill a random agent mid-run, because a swarm shrugs where a pipeline halts.

SWM·19settlement

The honest synthesis is hybrid — swarm dynamics for the messy divergent middle (analysis, planning, exploration), strict pipeline for the convergent human-facing edges (spec confirmation, commit, merge).

SWM·20settlement

Swarm for exploration and pipeline for delivery makes the orchestrator responsible only for the two boundaries Deep actually cares about: what was asked, and what shipped.

THE SYNTHESIS

Five lenses, 127 ideas, and then the collapse — where separate ideas turn out to have been the same idea wearing different clothes, and one structural cut ends the argument.

01

One plane, not three

Two-channel output, orchestrator-holds-pointers and runtime-writes-telemetry are one principle — separate the control plane from the evidence plane; build the evidence plane once and all three come free.

02

Git is five systems at once

Git-as-message-bus solves comms, observability, replay, flight recorder and swarm stigmergy with a single decision.

03

Policy becomes physics

Capability tokens convert the jira ownership rule from policy into physics — agents cannot disobey what they cannot reach.

04

The hidden axis is reversibility

Reversibility not trust is the hidden axis under the autonomy dial, trust collapse and risk tiers — blast radius is engineerable.

05

The wrong resource was optimized

Deep optimized the wrong resource: compute is pooled and cheap, context and history are scarce, so recycle compute aggressively and keep artifacts forever.

06

Terseness was never the metric

Minimal-output-to-save-tokens was the wrong goal — three lenses converged independently; the metric is tokens-per-merged-feature and terseness barely moves it while causing rework.

07

Memory is the missing compounding asset

The Historian plus cross-repo memory plus waggle dance are one idea — memory across features and products is the compounding advantage and is absent from the current spec.

08 ▚ Breakthrough

Make the orchestrator a dumb deterministic workflow engine with intelligence only at the leaves.
