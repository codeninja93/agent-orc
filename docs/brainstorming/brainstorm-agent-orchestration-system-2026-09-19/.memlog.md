- (technique) started TRIZ Contradiction
- (insight by coach) Twelve core contradictions sit inside the spec - each one Deep currently resolves by trading off, and TRIZ says most can be won on both sides by separating in time, space, or scale
- (idea by coach) Context contradiction (agents need rich context but must emit few tokens) resolved by separation in space: rich context lives in the agent own scratch on disk, only a thin schema crosses the boundary
- (idea by coach) Same contradiction resolved by separation in time: rich context during the exploration turns, compressed summary only at handoff - compression becomes a pipeline step not a standing constraint
- (idea by coach) Retrieval-not-injection: agents pull the context they need on demand rather than being handed everything up front, making context cost proportional to actual need
- (idea by coach) Orchestrator holds pointers not content: a manifest of artifacts with one-line summaries, reading a full artifact only when a decision requires it - orchestrator context is an index not a library
- (idea by coach) Rolling orchestrator: re-instantiate the orchestrator per phase from a durable state file so context never accumulates - state is on disk, context is disposable
- (idea by coach) Autonomy-versus-control dissolves once the real variable is named as reversibility not trust - auto-approve reversible actions, gate irreversible ones
- (idea by coach) Undo-first design: engineer everything to be reversible (worktree, branch, canary, auto-revert) and then full autonomy becomes safe by construction
- (idea by coach) Merge-conflict predictor: a cheap agent checks which files in-flight features touch and serializes only the overlapping ones - isolation by default, coordination only on collision
- (idea by coach) Shared read-only knowledge base plus per-feature code overlay: knowledge is shared while code stays isolated, winning both sides of the isolation contradiction
- (idea by coach) Split the jira agent into a deterministic cache plus an LLM shim so the ownership bottleneck disappears - 80 percent of requests become local reads
- (idea by coach) Read-replica pattern for owned domains: any agent may read a cached snapshot, only the owning agent may write - preserves single-writer discipline without serializing readers
- (idea by coach) Provision-ahead: predict resource needs from the plan and warm containers during the planning phase, hiding provisioning latency in time that was already being spent
- (idea by coach) A cheap executor paired with a stronger reviewer is frequently cheaper than a strong executor alone - buy verification not generation
- (idea by coach) Decomposition as a cost strategy: when a cheap model fails, the right move is often splitting the task smaller rather than escalating to a bigger model
- (idea by coach) Fidelity sampling for observability: full transcripts retained for failed runs, compressed summaries for successful ones - detail where it actually pays
- (idea by coach) Observability written by the runtime not by the agents: the harness records what agents did so agents never spend tokens describing themselves - free telemetry
- (idea by coach) Parallelism bounded by conflict domain rather than by a fixed count: run as many features at once as have disjoint file sets
- (idea by coach) Two-phase sandbox: a provisioning phase with network access to install dependencies, then network-off for execution - safety and capability separated in time
- (idea by coach) Egress allowlist proxy so agents keep network access but only to approved hosts, every call logged
- (idea by coach) Pipeline the phases so verification of feature N runs concurrently with planning of feature N+1, hiding verification latency entirely
- (idea by coach) Progressive verification: lint on every file write, tests on every logical chunk, full suite once at the end - fast feedback without paying full-suite cost repeatedly
- (idea by coach) Generic engine plus per-project profile: the orchestration engine is universal and every scrap of project knowledge lives in one profile file (stack, commands, conventions, resources)

- (technique) started Swarm Logic
- (insight by coach) Forbidding the master plan exposes that most of the orchestrator job is work ASSIGNMENT, which a shared queue plus local rules does for free - the orchestrator real irreducible job is the human contract, not coordination
- (idea by coach) Stigmergy via the filesystem: agents leave marks (failing tests, TODO files, lint errors) and other agents are attracted to them - a failing test IS the pheromone, no coordinator required
- (idea by coach) Three dumb local rules replace the assignment logic: fix a failing test you can fix, claim any work item matching your capability, write a note and die if you cannot progress in N steps
- (idea by coach) Claim-by-lockfile work distribution eliminates the assignment step entirely and makes concurrency safe with no central scheduler
- (idea by coach) Ant-colony task allocation with response thresholds: the longer a task waits and the more important it is, the more likely a lower-threshold agent picks it up - load balances itself
- (idea by coach) Emergent decomposition: rather than a planner breaking the feature down, spawn agents that each attempt the whole feature and abort where competence runs out, leaving a note - the breakdown is discovered not designed
- (idea by coach) Evolutionary variant selection: N executors, brutal selection on test pass rate and diff size, then breed the survivor approach into the next round
- (idea by coach) Quorum sensing as a spec-drift defense: do not begin executing until 2 of 3 analysts independently converge on the same interpretation of the request
- (idea by coach) Waggle dance: an agent that found a productive approach broadcasts a compact how-I-did-it that other agents copy, giving cross-feature learning without designing a central memory
- (idea by coach) Termite-mound bounded build: agents may only modify files adjacent to already-changed files, naturally constraining diff sprawl
- (idea by coach) Capability-tagged work queue where agents pull what matches their profile - adding a new agent type is just adding a new puller, making the system trivially extensible
- (idea by coach) Death as a feature: agents are cheap and mortal, any agent exceeding its step budget dies and leaves its partial work as a pheromone for the next one - robustness through disposability
- (idea by coach) In a swarm there is no jira agent, jira is simply another pheromone source polled into the shared work queue
- (idea by coach) Local rules generate observability for free - the event log of claims, releases and deaths IS the timeline the dashboard renders
- (idea by coach) Pheromone decay: stale work items lose priority and eventually expire, preventing a growing graveyard of half-finished tasks
- (idea by coach) Recruitment instead of escalation: a stuck agent raises its pheromone to attract a stronger model rather than escalating up a chain of command - the model ladder as swarm recruitment
- (idea by coach) No global state at all: everything an agent needs lives in the worktree it is standing in, giving portability and resumability for free
- (idea by coach) Minimal viable swarm is radically cheaper to build than eight bespoke role agents - three rules, one shared queue, N identical workers differing only in tool grants
- (idea by coach) Anti-fragility architecture test: kill a random agent mid-run, because a swarm shrugs where a pipeline halts
- (idea by coach) The honest synthesis is hybrid - swarm dynamics for the messy divergent middle (analysis, planning, exploration), strict pipeline for the convergent human-facing edges (spec confirmation, commit, merge)
- (idea by coach) Swarm for exploration and pipeline for delivery makes the orchestrator responsible only for the two boundaries Deep actually cares about: what was asked, and what shipped
- (insight by coach) SYNTHESIS: (1) Two-channel output, orchestrator-holds-pointers and runtime-writes-telemetry are one principle - separate the control plane from the evidence plane; build the evidence plane once and all three come free. (2) Git-as-message-bus solves comms, observability, replay, flight recorder and swarm stigmergy with a single decision. (3) Capability tokens convert the jira ownership rule from policy into physics - agents cannot disobey what they cannot reach. (4) Reversibility not trust is the hidden axis under the autonomy dial, trust collapse and risk tiers - blast radius is engineerable. (5) Deep optimized the wrong resource: compute is pooled and cheap, context and history are scarce, so recycle compute aggressively and keep artifacts forever. (6) Minimal-output-to-save-tokens was the wrong goal - three lenses converged independently; the metric is tokens-per-merged-feature and terseness barely moves it while causing rework. (7) The Historian plus cross-repo memory plus waggle dance are one idea - memory across features and products is the compounding advantage and is absent from the current spec. (8) BREAKTHROUGH: make the orchestrator a dumb deterministic workflow engine with intelligence only at the leaves; the orchestrator is a conversation and a scheduler fused together that should be split, leaving only the Interviewer as a live LLM. (9) Build order: event log plus git-as-bus, then deterministic engine with 3 agents not 8, then TUI on the event stream, then shadow mode to measure, then earn autonomy - shadow mode and dry run exist to tell Deep when to STOP building, the defense against maintenance burden as the likeliest project-killer.
