- (technique) started Empathy Map
- (insight by coach) Deep at 9am with three features in flight says what is the status and did it ask me something, thinks is it stuck or thinking and I could have done this myself by now, does constant alt-tabbing and diff-skimming between meetings, and feels low-grade spend anxiety plus guilt about not reviewing properly
- (idea by coach) Status must be answerable in under two seconds WITHOUT reading - one glanceable line per feature, and if a paragraph is needed to know the state the interface has already failed
- (idea by coach) Visually distinguish stuck from thinking, because that ambiguity is the single largest source of anxiety - a heartbeat pulse naming the current step, never an undifferentiated spinner
- (idea by coach) Deep three-feature mental model decays fast between meetings, so every notification must reload the context itself rather than assuming he still holds it
- (idea by coach) Never interrupt with anything that cannot be resolved in ten seconds - anything longer gets queued for a boundary
- (idea by coach) Batch interruptions to natural boundaries with a do-not-disturb-until mode that queues questions rather than firing them into a meeting
- (idea by coach) Cost needs a permanently visible running number, because spend anxiety is continuous and a report he has to request does not relieve it
- (idea by coach) He skims diffs rather than reading them, so the system must say WHERE to look - the risky twelve lines of a four-hundred-line diff - giving review guidance instead of review dumps
- (idea by coach) I-could-have-done-this-myself is the churn signal, so surface elapsed-versus-estimate continuously to enable killing early instead of sunk-costing
- (idea by coach) The system must state its own confidence AND what it did not verify, so trust is calibrated rather than blind and the guilt about skipping review is resolved honestly
- (idea by coach) Make just-do-it a real first-class command meaning stop asking, use judgment, I will review at the end
- (idea by coach) Make rejection cheap: one keystroke plus a reason, and that reason becomes a decision-ledger entry automatically
- (idea by coach) Answer in the terminal he is already in - the web app is for LOOKING, the terminal is for ANSWERING, and never force a context switch to reply
- (idea by coach) Every question carries its own mini-brief so it is answerable without loading the full feature context back into his head
- (idea by coach) Target the emotional register of a competent colleague reporting in, not a dashboard demanding attention
- (idea by coach) Silence must be a trustworthy contract meaning no news is good news, or he will poll anxiously and the whole ambient design collapses
- (idea by coach) Show what he actually asked for alongside what is being built, because at 9am he does not remember his own 4pm phrasing
- (technique) started Worst Possible Idea
- (insight by coach) Designing the most infuriating possible interface surfaces the real requirements faster than designing the good one, because every irritation inverts cleanly into a rule
- (idea by coach) Worst: asks a question every ninety seconds. Flip: question compression plus interrupt budget plus batching to boundaries
- (idea by coach) Worst: asks vague open questions like how should I handle errors. Flip: every question ships with a recommended default and two or three concrete options, never open-ended
- (idea by coach) Worst: asks things it could have answered itself. Flip: answer-from-repo first with a tracked deflection rate
- (idea by coach) Worst: dumps two thousand tokens of reasoning per update. Flip: one line by default, expandable on demand
- (idea by coach) Worst: notifies on every agent state change. Flip: notify only on exceptions, decisions and completion
- (idea by coach) Worst: requires the web UI to do anything. Flip: terminal-complete with the web app strictly optional
- (idea by coach) Worst: asks the same question again next week. Flip: the decision ledger, checked before any question is asked
- (idea by coach) Worst: says done when it is not. Flip: every completion states what was verified and what was not
- (idea by coach) Worst: blocks silently waiting for input. Flip: escalating notification - terminal bell, then OS notification, then after N minutes proceed with the stated default
- (idea by coach) Worst: loses everything when the terminal closes. Flip: durable state with resume-by-feature-name
- (idea by coach) Worst: reports progress as a meaningless percentage. Flip: name the current step and the next gate
- (idea by coach) Worst: demands answers in a rigid format. Flip: free text in, the Interviewer does the parsing - never make the human do machine work
- (idea by coach) Worst: wakes him at 3am. Flip: quiet hours and async-by-default delivery
- (idea by coach) Worst: buries the question in scrollback. Flip: a persistent question slot that never scrolls away
- (idea by coach) Worst: offers eight options. Flip: at most three plus an explicit something-else escape
- (idea by coach) Worst: explains its reasoning when he asked for a decision. Flip: answer first, reasoning strictly on request
- (idea by coach) Worst: phrases and formats every message differently. Flip: a stable learnable grammar of message types he can pattern-match at a glance
- (idea by coach) Worst: makes him remember agent names and run IDs. Flip: address everything by feature name, never by agent identifier
- (idea by coach) Worst: cannot be stopped mid-run. Flip: interruptible at every step with clean partial state preserved
- (idea by coach) Worst: asks approval for reversible things. Flip: gate only the irreversible - the reversibility axis surfacing again from the interface side
- (idea by coach) Worst: cheerful anthropomorphic filler around every message. Flip: zero pleasantries, information density, warmth expressed through competence not chattiness
- (technique) started Sci-Fi Artifact From the Future
- (insight by coach) Describing concrete artifacts from the world where this already works - actual terminal messages, cards and commands - forces specificity that abstract interface principles never reach
- (idea by coach) The morning brief: six lines at 9am - three features, one needs you for thirty seconds, one merged overnight for two dollars ten, one blocked on a flaky payments test seen four times before - which reverse-engineers into overnight autonomy, cost tracking, pattern memory and triage ranked by attention cost
- (idea by coach) The one-question interrupt card shows the question, the recommended answer, the consequence of each option, AND what it will do if he says nothing in ten minutes - default-on-timeout is the mechanic that makes async tolerable
- (idea by coach) The spec echo card: five acceptance criteria before any work starts, with reply go or edit any line - editing the criteria in place beats re-prompting from scratch
- (idea by coach) The kill card: feature X has spent eight dollars and forty minutes against a three dollar fifteen minute estimate - continue, narrow scope, kill, or take over - making early exit a designed moment rather than a failure
- (idea by coach) The handoff document written when the system gives up reads like a colleague note, not a stack trace, and is the artifact that determines whether giving up feels like competence or failure
- (idea by coach) The review request: twelve of four hundred lines need your eyes, and here is why each one does
- (idea by coach) The weekly self-report: fourteen features shipped, you corrected me three times, here is what I learned, and here are two rules I would like to add to the ledger - the system proposing its own memory writes for approval
- (idea by coach) The trust meter: per-area accuracy history like auth nine of ten merged unchanged, payments three of seven - autonomy derived from evidence rather than granted by vibes
- (idea by coach) The undo command: one word that cleanly reverts a merged feature, and its mere existence is what makes delegation feel safe
- (idea by coach) The ambient status line as a single tmux or shell prompt segment - always visible, never demanding, the opposite of a notification
- (idea by coach) The what-did-you-do-last-night replay narrated in plain language rather than raw events, because he wants the story not the log
- (idea by coach) The new-repo onboarding conversation: the bootstrap agent interviews HIM for five minutes once, then never asks those questions again
- (idea by coach) A notification he actually enjoys receiving - merged, four files, tests green, one dollar twenty, nothing needed from you - because the shape of good news matters as much as the shape of bad news
- (idea by coach) The I-am-confused signal as a distinct honest state, so uncertainty surfaces as uncertainty rather than as a confident wrong answer
- (idea by coach) The receipt: a single end-of-day summary of spend and outcomes that resolves the anxiety daily instead of letting it accumulate
- (technique) started Metaphor Mapping
- (insight by coach) Seven metaphors for the Interviewer each donate a different mechanism, and the autopilot one donates the most safety-critical concept in the entire session - mode confusion
- (idea by coach) Chief of staff: the Interviewer real KPI is QUESTIONS NOT ASKED, and it should report I handled it far more often than it asks what should I do
- (idea by coach) Chief of staff: a standing brief format that never varies, so he learns to read it in one saccade rather than parsing fresh prose each time
- (idea by coach) Chief of staff: it owns the calendar of his attention and is accountable for spending it well
- (idea by coach) Air traffic control: a compact strip per feature holding everything needed to resume it cold
- (idea by coach) Air traffic control: constrained phraseology - a small fixed vocabulary of message types rather than free prose
- (idea by coach) Air traffic control: READBACK is spec echo - the system restates his instruction before acting on it, and the readback is the contract
- (idea by coach) Air traffic control: separation minima map to conflict domains, and handoff between controllers maps to the artifact passed between phases
- (idea by coach) Surgical nurse: anticipate the next instrument and have it ready before it is requested - pre-fetch what he will need at the next decision point
- (idea by coach) Surgical nurse: the sponge count is a reconciliation checklist that must balance before closing, and nothing merges until it does
- (idea by coach) Surgical nurse: speak up only when something is wrong, which is the purest form of the silence-means-success contract
- (idea by coach) Newsroom editor: every report follows the inverted pyramid with the most important thing first and detail decaying downward
- (idea by coach) Newsroom editor: headline discipline means every message carries a one-line headline that stands completely alone
- (idea by coach) Newsroom editor: sourcing rules map to provenance - no claim without a traceable source
- (idea by coach) Sous chef and expediter: a short rhythmic predictable calling voice, with features as tickets moving through a pass
- (idea by coach) Junior developer being mentored: correction must be cheap to give AND must stick permanently, which is the decision ledger justified from the human side
- (idea by coach) Junior developer being mentored: rope is earned per area rather than granted globally
- (idea by coach) Autopilot: MODE VISIBILITY is safety-critical - he must always know at a glance whether the system is in autonomous, asking, or paused mode
- (idea by coach) Autopilot: mode confusion is the classic accident class in aviation, and it is the exact failure waiting in a system with autonomy tiers - name the current mode in the prompt line permanently
- (idea by coach) Autopilot: disengagement must be instant, obvious and always available, with a single physical gesture that always means stop
- (idea by coach) Autopilot: standard callouts at phase transitions so the human builds an accurate mental model of what the machine is doing without asking
- (technique) started Shadow Work Mining
- (insight by coach) What Deep is actually avoiding is more predictive of adoption than any feature - the fears are owning incomprehensible code, losing the feel of his own codebase, burning money while asleep, and quietly preferring to build the tool rather than the products
- (idea by coach) Fear of owning code he does not understand means comprehensibility is a hard requirement not a nicety - the system must write in HIS idiom and the review artifact must make the diff understandable, not merely correct
- (idea by coach) Fear of losing the feel for his own codebase argues for deliberately keeping him in the loop on architecture while delegating mechanics - the parts he enjoys are a design input, not an inefficiency to optimize away
- (idea by coach) The honest shadow is that building the orchestrator is more fun than building the products, so the real success metric must be shipping velocity of actual products, not sophistication of the tool
- (idea by coach) Fear of burning money overnight is resolved not by a cap alone but by a morning receipt, so the anxiety closes daily instead of compounding
- (idea by coach) Fear of looking bad when it commits something dumb makes attribution an EMOTIONAL design question - PR by default rather than direct commit, and a clear convention for whose name is on the commit
- (idea by coach) Deep does not want to be the orchestrator user, he wants to be a builder with leverage, so the interface must feel like his own capability rather than a product he operates
- (idea by coach) He will not do thorough reviews because reviewing is boring, so design honestly for that - make verification strong enough that skimming is the RATIONAL choice rather than building a beautiful review UI he will not open
- (idea by coach) Fear of silent degradation - it works for three months then quietly gets worse - is exactly what the weekly self-report and the trust meter exist to make visible
- (idea by coach) The secret wish is to describe a feature and go make coffee, which means the true north metric is percentage of features completed with ZERO mid-flight interruptions
- (idea by coach) An interruption costs roughly fifteen minutes of his focus, so the system should be willing to spend a great deal of compute to avoid one - quantifying the exchange rate between tokens and attention is the single most clarifying idea for the whole interface
- (idea by coach) He will blame the system for his own vague specs, and spec echo protects both parties because the echo becomes the contract
- (idea by coach) Uncanny register risk: too human a question is unsettling and too robotic a question gets ignored, so aim squarely at colleague - not butler, not robot
- (idea by coach) Resentment risk: if the system asks him to do something tedious that it could have done, trust drops faster than it does from an outright bug
- (idea by coach) He secretly wants to be impressed, and a system that occasionally shows him something he did not know about his own codebase buys more trust than one that is merely correct
- (insight by coach) SYNTHESIS: (1) Master variable is the exchange rate between tokens and attention - an interruption costs about fifteen minutes of focus, so the system should spend large amounts of compute to avoid a single question, which retroactively settles session one token-minimal premise because attention is orders of magnitude more expensive than tokens. (2) Three metaphors independently produced speak-only-when-something-is-wrong, and that silence-means-success contract is only trustworthy if detection is reliable - so the silence contract is actually a verification requirement wearing an interface costume. (3) Mode confusion is the aviation accident class already waiting in a design with autonomy tiers - permanent mode display in the prompt line, instant disengage, standard callouts at transitions; modes are how reversibility gets communicated to the human. (4) Third convergence across three sessions: spec echo found via threat-modeling drift and ATC readback found via metaphor are the same mechanism reached by unrelated routes, so it is load-bearing and should be built first. (5) Default-on-timeout is the mechanic that makes async tolerable - every question states what happens if ignored, reconciling never-block with do-not-act-unapproved and making non-response a valid input. (6) Shadow work reframes the success metric to percentage of features completed with ZERO mid-flight interruptions, with shipping velocity of actual products as the counter-metric defending against the tool-building-as-procrastination shadow. (7) Two unspecced essentials: attribution is an emotional design question (whose name on the commit, PR versus direct push) and the register must be colleague - not butler, not robot - warmth through competence with zero pleasantries. (8) BUILD ORDER CONSEQUENCE: the interface is not phase two, because the v0 spine exists to run shadow mode and shadow mode has no autonomy at all - it only reports - so shadow mode is entirely an interface product and the morning brief, the one-question card with default-on-timeout, and mode display ARE v0. (9) Worst Possible Idea produced the most directly implementable output of any lens across three sessions: twenty-one irritations inverting into twenty-one concrete interface rules, effectively a free interface spec.
