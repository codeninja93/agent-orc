Lens Istarted — Job to Be DoneStratum 01

What memory is hired to do

There is no single thing called memory — there are about ten distinct jobs with different shapes, lifetimes and retrieval patterns, and building one vector store for all of them is the classic failure.

19 ideas · 10 postings · 9 terms

Open requisitions

Attention saved is the only accepted currency
01

Do not make me explain my conventions twice

But the best form of a remembered convention is not retrieval, it is a generated lint rule or test that fails the build, costing zero tokens at read time.

02

Do not rewrite code that already exists

Prior-art retrieval keyed on the PLAN not the prompt, running after decomposition using concrete subtasks as queries.

03

Do not repeat a mistake that already cost money

And the right artifact for a remembered failure is a regression test, not a note.

04

Make an agent productive in an unfamiliar region of the repo fast

Region expertise memory attached to directories.

05

Let product B benefit from product A

Cross-repo pattern memory — the only job that justifies the whole system existing across projects.

06

Tell me WHY the code is like this

Rationale memory whose primary consumer is human, so it must be readable prose not machine soup.

07

Estimate what this feature will cost before committing budget

Historical cost memory answering: features touching auth have averaged X dollars and Y rework cycles.

08

Know which areas are fragile and which tests are flaky

Risk memory used as a ROUTING input that selects verification depth, not as context.

09

Resume a feature paused three weeks ago

Episodic memory, which is just an append-only per-feature log and is nearly free.

10

Survive a model version change without re-teaching everything

Memory stored as structured facts rather than tuned prompt text.

Terms of employment — the nine clauses attached to every hire

  1. The real reframe. Deep is not hiring memory, he is hiring do-not-waste-my-attention-twice — every memory feature must be justified by a specific attention saving.
  2. Memory that enforces itself beats memory that must be recalled. Convert every remembered preference into an executable check wherever the preference is checkable.
  3. Memory write is a privilege, not a default. Only verified and merged outcomes may write to long-term memory; failed experiments write to episodic only — this is the primary defense against memory poisoning.
  4. Every entry carries a decay policy chosen at write time: permanent, until-refactor, N-features, or this-session-only.
  5. Learning is a pipeline step with an owner. The committer agent writes what was learned, so memory is a first-class output rather than a hopeful side effect.
  6. A hard read budget per feature caps how many tokens of memory may enter context, which forces ranking quality to actually matter instead of being decorative.
  7. Negative memory — we tried this and it did not work — is higher value per token than positive memory, and almost nobody builds it.
  8. Record the QUESTION SHAPE alongside the answer in the decision ledger, so similar-but-not-identical questions can be recognized and deflected.
  9. If a new human developer cannot read the memory store, it is too machine-shaped to audit and will silently rot.
Lens IIstarted — Nature's SolutionsStratum 02

A field guide to organisms that remember

Biology solved memory many times over and the transfers are unusually literal here — the strongest is sleep consolidation, which says do not write long-term memory during the run at all.

19 specimens · collected in one pass

Spec. 01

Sleep consolidationHippocampus → neocortex

A consolidation job runs BETWEEN features or nightly, compacting fast lossy episodic logs into slow structured durable facts — tokens are cheap then and outcomes are finally known.

Transfer — never write long-term during the run
Spec. 02

Immune memoryMemory B cells

Remember specific threats and respond faster on re-exposure, so a past bug pattern triggers a pre-emptive check when something similar appears.

Transfer — pattern-triggered pre-emptive checks
Spec. 03

VaccinationDeliberate re-exposure

Deliberately re-expose the system to a past bug so it builds an antibody in the form of a permanent test.

Transfer — failures become permanent tests
Spec. 04

Bacterial CRISPRStored viral fragments

Literally stores fragments of past viral attackers in its own genome — store the diff that caused each past incident as a recognition signature.

Transfer — the diff is the signature
Spec. 05

Synaptic pruningUse it or lose it

Memory entries that are never retrieved get deleted, so track retrieval hit-counts from day one or you can never prune safely.

Transfer — hit-counts from day one
Spec. 06

MyelinationFast paths get faster

Frequently retrieved memories get promoted into the always-loaded project profile while rare ones stay in cold retrieval.

Transfer — promotion by frequency
Spec. 07

DNA versus epigeneticsSlow genome, fast switches

Cross-repo memory is the slow shared genome; the per-repo profile is the fast local epigenetic layer that switches genes on and off.

Transfer — two speeds, one substrate
Spec. 08

Spores and seedsRegeneration from a kernel

A tiny seed file per repo that can regenerate the entire memory index from git history, so losing the index is an inconvenience not a catastrophe.

Transfer — index is disposable
Spec. 09

Coral and stromatolitesAccreted skeletons

Structure accreted by many small organisms each building on the last skeleton — the codebase and its AGENTS.md files ARE the memory, accreted feature by feature.

Transfer — the artifact is the record
Spec. 10

OctopusDistributed cognition

Puts most neurons in the arms — per-directory memory located where the work happens beats a central store.

Transfer — memory lives at the limb
Spec. 11

Elephant matriarchConsulted in crises

Holds long-term ecological memory the herd relies on only in crises — the Historian should be consulted at decision points, not constantly.

Transfer — the Historian is not a daemon
Spec. 12

Migratory magnetoreceptionNavigation by stable field

Navigates by a stable external field — anchor memory to the most stable references available, never to line numbers.

Transfer — anchor to what does not move
Spec. 13

Slime moldReinforced paths

Rebuilds optimal networks by reinforcing used paths and starving unused ones — the retrieval graph itself becomes the memory, with structure encoding what matters.

Transfer — the graph is the content
Spec. 14

Tardigrade cryptobiosisSuspend and resume

Suspend completely and resume losing nothing — the model for hibernating a paused feature.

Transfer — lossless pause
Spec. 15

Squirrel scatter-hoardingAccepted loss

Accepts that some caches are lost — embrace lossy redundant memory over a perfect fragile index.

Transfer — redundancy over perfection
Spec. 16

Bird song learningCritical period

Has a critical period with a tutor, then crystallizes — learn intensively during repo bootstrap, then stabilize the profile.

Transfer — bootstrap, then crystallize
Spec. 17

Adaptive forgettingSpecifics out, pattern in

Organisms forget specifics to generalize, and aggressive forgetting of specifics while keeping the pattern is what stops memory becoming a liability after refactors.

Transfer — forgetting is a feature
Spec. 18

Lichen symbiosisTwo organisms, one memory

Two organisms whose combined memory exceeds either — the codebase holds structure, the event log holds history, and neither alone is memory.

Transfer — structure + history = memory
Spec. 19

Horizontal gene transferAcross species lines

Lets bacteria swap useful genes across species lines — a deliberate mechanism to transplant a proven pattern from repo A into repo B, not merely hope retrieval finds it.

Transfer — transplant, do not hope
Lens IIIstarted — Cross-PollinationStratum 03

Borrowed from twenty-three drawers

Memory is a solved problem in a dozen industries, and the single biggest scope cut available is realizing git already IS most of the memory store Deep was planning to build.

23 index cards · filed by discipline

Databases · 01

Write-ahead log plus compaction

Exactly the episodic-log plus consolidation pattern, arrived at independently from sleep biology — two fields converging is a strong signal it is correct.

Convergence
Databases · 02

Separate the index from the store

So the index can be rebuilt, reshaped or thrown away without touching the durable record.

Databases · 03

Materialized views

Precomputed answers to the questions agents ask most, refreshed on merge rather than computed per query.

Version control

git blame and git log already ARE memory

So build nothing that stores what git can already answer — the largest single scope reduction available.

Largest scope cut
Search engines

Authority and recency, not raw similarity

Memory from merged and shipped code must rank above memory from an abandoned branch.

CPU cache

Design memory explicitly as tiers

With sizes and latencies — always-loaded profile as L1, per-region AGENTS.md as L2, retrieval index as L3, raw git history as disk — with defined promotion and eviction between them.

Zettelkasten

Atomic notes, one fact each

Densely linked, with structure emerging from links rather than an imposed taxonomy.

Aviation · NTSB

The airworthiness directive

A flight recorder plus mandatory incident reports, where a single finding becomes a directive binding on every aircraft — an incident in one repo becomes a guardrail in all of them.

Medicine

A repo has a chart

Known allergies (what breaks it), chronic conditions (tech debt), past procedures (major refactors) — and you read the chart before operating.

Law · precedent

A decision can be OVERRULED

Decisions cite prior decisions, and a decision can be explicitly overruled with a stated reason while the old one stays visible — this is the clean answer to memory that has become wrong.

Accounting

Double-entry provenance

Every memory claim carries provenance and can be audited back to its source event.

Library science

A controlled vocabulary for tags

So the store stays queryable as it grows past the point where anyone remembers what they called things.

Wikipedia

Flag contested facts, never overwrite

Contested facts get flagged rather than silently overwritten, and memory needs a review mechanism once more than one agent writes to it.

Kitchen

Mise en place

Pre-warm the memory context for a feature during the planning phase so execution never stalls waiting on retrieval.

Casino

Player tracking per area

Compute expected value per area of the codebase and learn which regions reliably cost more than estimated.

Sports

Film study reviews losses more than wins

Consolidation should weight failures substantially higher than successes.

Toyota TPS

Standard work, andon, kaizen

Standard work is convention memory, the andon cord is the escalation path, and every kaizen is a memory write with a named owner.

Actuarial

Tables price risk from history

Route model tier and verification depth by the historical risk profile of the area being touched.

Tradecraft

Compartmentalization

Memory scoped by agent capability, so the executor never receives the entire project history it does not need.

Jazz

Standards make improvisation fast

A shared repertoire everyone knows is what makes improvisation fast — a library of known-good patterns per stack is the highest-leverage memory content.

Chess

Opening books

Precomputed known-good sequences for common positions, so common feature shapes (add a CRUD endpoint, add a migration, add a webhook) get a stored opening.

Air traffic control

The flight strip

The compact record handed between controllers means the agent-to-agent handoff artifact is itself the memory unit.

Changelogs

Changelogs and semver

Memory of what changed and why, in a format humans already know how to read.

Drilled down through ten thousand features

Stepping the memory layer through 1, 100, 1000 and 10000 features shows the dominant cost FLIPS from writing memory to invalidating it, which reverses what the design should optimize for.

Across five repos patterns transfer; across fifty they drown

The per-repo noise swamps cross-repo signal unless cross-repo memory stores only abstract patterns and never concrete snippets.

Abstract only

Survives every rung

The append-only event log and git itself — because both are immutable and always true.

Breaks at every single rung

Anything storing file paths, line numbers or code snippets.

Stable anchors, ranked by durability

  1. 01test names
  2. 02public API symbols
  3. 03module names
  4. 04file paths
  5. 05line numbers

Line numbers are never acceptable anchors. The design rule falling out of the ladder: memory stores questions and their durable answers plus pointers to stable anchors, never copies of code.

▸ SCHEMA

What transfers between products is how-we-do-auth, never the auth code itself — this single rule determines the schema of cross-repo memory.

▸ INVALIDATE

Hook memory invalidation to the refactor itself — the committer detects renames and rewrites anchors as part of the commit, so memory cannot drift behind the code.

▸ SWEEP

A periodic re-validation sweep samples memory entries and checks their anchors still resolve, flagging the dead ones instead of waiting to be misled by them.

▸ REBUILD

Make memory rebuildable: if ninety percent can be regenerated from git history plus the event log, then corruption stops being a crisis and the schema becomes free to change.

▸ 10 YEARS

At the ten-year rung the model has changed many times — memory as structured facts and tests survives that, memory as tuned prompt text does not.

▸ FAR RUNG

At the absurd far rung the memory becomes more valuable than the code, because code is regenerable while accumulated decisions and constraints are not — which inverts what you back up and what you version.

▸ SCOPE

The consolidation job is the ONLY genuinely new subsystem worth building for memory, because everything else is querying git and the event log.

▸ KILL TEST

Measure memory ROI directly as retrieval token cost versus measured reduction in rework, and delete the memory layer outright if that number is not positive.

Entry 88 · the single consolidation pass

Eight things that survive the night

Seventy-nine ideas were logged fast and lossy. This is what remained once the outcomes were known and the tokens were cheap.

01

Two fields walked to the same door

The strongest signal is convergence — sleep consolidation in biology and write-ahead-log plus compaction in databases are the same design reached independently, both saying never write long-term memory during the run; log fast and lossy, consolidate afterward when outcomes are known and tokens are cheap.

02

The biggest scope cut is a tool you already run

Git already IS most of the memory store, so build nothing git log and git blame can answer, and require memory to be rebuildable from git plus the event log — memory becomes an index over things already held, making schema change free and corruption survivable.

git log
git blameThe store already exists. Build the index only.

03

Memory that enforces itself costs nothing to read

Conventions become lint rules, failures become regression tests, incidents become guardrails — so the layer's real job is CONVERTING memory into executable artifacts, and falling back to retrieval only for the irreducibly fuzzy.

0 tokens at read time
04

The cost flips from writing to invalidating

The trap from the horizon ladder is that the dominant cost flips from writing memory at 100 features to INVALIDATING it at 1000 — so decay policy at write time, durability-ranked anchors with line numbers banned, and invalidation hooked to the refactor commit must all be day-one decisions.

05

Two cheap unbuilt wins

Memory as a ROUTING input — risk memory picks verification depth, cost memory picks model tier — and negative memory, which is worth more per token than positive memory.

06

Patterns cross repos; snippets never do

Cross-repo memory must store abstract patterns never snippets — how-we-do-auth, not auth code — and that single rule determines the schema.

07

The v0 verdict holds

Agreeing with session one: build no memory layer, keep only the episodic event log, which is simultaneously flight recorder, timeline, resume mechanism and the substrate for everything later.

08

The log you are reading is the spec

Self-referential: the memlog pattern this session ran on — append-only, one line per idea, never edited, a single consolidation pass at the end — IS the architecture to build.
