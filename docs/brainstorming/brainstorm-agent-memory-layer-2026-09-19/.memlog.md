- (technique) started Job to Be Done
- (insight by coach) There is no single thing called memory - there are about ten distinct jobs with different shapes, lifetimes and retrieval patterns, and building one vector store for all of them is the classic failure
- (idea by coach) Job 1 do not make me explain my conventions twice - but the best form of a remembered convention is not retrieval, it is a generated lint rule or test that fails the build, costing zero tokens at read time
- (idea by coach) Memory that enforces itself beats memory that must be recalled - convert every remembered preference into an executable check wherever the preference is checkable
- (idea by coach) Job 2 do not rewrite code that already exists - prior-art retrieval keyed on the PLAN not the prompt, running after decomposition using concrete subtasks as queries
- (idea by coach) Job 3 do not repeat a mistake that already cost money - and the right artifact for a remembered failure is a regression test, not a note
- (idea by coach) Job 4 make an agent productive in an unfamiliar region of the repo fast - region expertise memory attached to directories
- (idea by coach) Job 5 let product B benefit from product A - cross-repo pattern memory, the only job that justifies the whole system existing across projects
- (idea by coach) Job 6 tell me WHY the code is like this - rationale memory whose primary consumer is human, so it must be readable prose not machine soup
- (idea by coach) Job 7 estimate what this feature will cost before committing budget - historical cost memory answering features touching auth have averaged X dollars and Y rework cycles
- (idea by coach) Job 8 know which areas are fragile and which tests are flaky - risk memory used as a ROUTING input that selects verification depth, not as context
- (idea by coach) Job 9 resume a feature paused three weeks ago - episodic memory, which is just an append-only per-feature log and is nearly free
- (idea by coach) Job 10 survive a model version change without re-teaching everything - memory stored as structured facts rather than tuned prompt text
- (idea by coach) JTBD reframe: Deep is not hiring memory, he is hiring do-not-waste-my-attention-twice - every memory feature must be justified by a specific attention saving
- (idea by coach) Memory write is a privilege not a default: only verified and merged outcomes may write to long-term memory, failed experiments write to episodic only - this is the primary defense against memory poisoning
- (idea by coach) Every memory entry carries a decay policy chosen at write time - permanent, until-refactor, N-features, or this-session-only
- (idea by coach) Learning is a pipeline step with an owner: the committer agent writes what was learned, so memory is a first-class output rather than a hopeful side effect
- (idea by coach) Hard read budget per feature caps how many tokens of memory may enter context, which forces ranking quality to actually matter instead of being decorative
- (idea by coach) Negative memory - we tried this and it did not work - is higher value per token than positive memory and almost nobody builds it
- (idea by coach) The decision ledger should record the QUESTION SHAPE alongside the answer so similar-but-not-identical questions can be recognized and deflected
- (idea by coach) If a new human developer cannot read the memory store, it is too machine-shaped to audit and will silently rot
- (technique) started Nature's Solutions
- (insight by coach) Biology solved memory many times over and the transfers are unusually literal here - the strongest is sleep consolidation, which says do not write long-term memory during the run at all
- (idea by coach) Sleep consolidation (hippocampus to neocortex): a consolidation job runs BETWEEN features or nightly, compacting fast lossy episodic logs into slow structured durable facts - tokens are cheap then and outcomes are finally known
- (idea by coach) Immune memory and memory B cells: remember specific threats and respond faster on re-exposure, so a past bug pattern triggers a pre-emptive check when something similar appears
- (idea by coach) Vaccination: deliberately re-expose the system to a past bug so it builds an antibody in the form of a permanent test
- (idea by coach) Bacterial CRISPR literally stores fragments of past viral attackers in its own genome - store the diff that caused each past incident as a recognition signature
- (idea by coach) Synaptic pruning: memory entries that are never retrieved get deleted, so track retrieval hit-counts from day one or you can never prune safely
- (idea by coach) Myelination: frequently retrieved memories get promoted into the always-loaded project profile while rare ones stay in cold retrieval
- (idea by coach) DNA versus epigenetics: cross-repo memory is the slow shared genome, the per-repo profile is the fast local epigenetic layer that switches genes on and off
- (idea by coach) Spores and seeds: a tiny seed file per repo that can regenerate the entire memory index from git history, so losing the index is an inconvenience not a catastrophe
- (idea by coach) Coral and stromatolites: structure accreted by many small organisms each building on the last skeleton - the codebase and its AGENTS.md files ARE the memory, accreted feature by feature
- (idea by coach) Octopus distributed cognition puts most neurons in the arms - per-directory memory located where the work happens beats a central store
- (idea by coach) Elephant matriarch holds long-term ecological memory the herd relies on only in crises - the Historian should be consulted at decision points, not constantly
- (idea by coach) Migratory magnetoreception navigates by a stable external field - anchor memory to the most stable references available, never to line numbers
- (idea by coach) Slime mold rebuilds optimal networks by reinforcing used paths and starving unused ones - the retrieval graph itself becomes the memory, with structure encoding what matters
- (idea by coach) Tardigrade cryptobiosis: suspend completely and resume losing nothing - the model for hibernating a paused feature
- (idea by coach) Squirrel scatter-hoarding accepts that some caches are lost - embrace lossy redundant memory over a perfect fragile index
- (idea by coach) Bird song learning has a critical period with a tutor then crystallizes - learn intensively during repo bootstrap, then stabilize the profile
- (idea by coach) Forgetting is adaptive: organisms forget specifics to generalize, and aggressive forgetting of specifics while keeping the pattern is what stops memory becoming a liability after refactors
- (idea by coach) Lichen symbiosis: two organisms whose combined memory exceeds either - the codebase holds structure, the event log holds history, and neither alone is memory
- (idea by coach) Horizontal gene transfer lets bacteria swap useful genes across species lines - a deliberate mechanism to transplant a proven pattern from repo A into repo B, not merely hope retrieval finds it
- (technique) started Cross-Pollination
- (insight by coach) Memory is a solved problem in a dozen industries, and the single biggest scope cut available is realizing git already IS most of the memory store Deep was planning to build
- (idea by coach) Databases: write-ahead log plus compaction is exactly the episodic-log plus consolidation pattern, arrived at independently from sleep biology - two fields converging is a strong signal it is correct
- (idea by coach) Databases: separate the index from the store so the index can be rebuilt, reshaped or thrown away without touching the durable record
- (idea by coach) Databases: materialized views as precomputed answers to the questions agents ask most, refreshed on merge rather than computed per query
- (idea by coach) Version control: git blame and git log already ARE memory, so build nothing that stores what git can already answer - the largest single scope reduction available
- (idea by coach) Search engines: memory from merged and shipped code must rank above memory from an abandoned branch - authority and recency signals, not raw similarity
- (idea by coach) CPU cache hierarchy: design memory explicitly as tiers with sizes and latencies - always-loaded profile as L1, per-region AGENTS.md as L2, retrieval index as L3, raw git history as disk - with defined promotion and eviction between them
- (idea by coach) Zettelkasten: atomic notes, one fact each, densely linked, structure emerging from links rather than an imposed taxonomy
- (idea by coach) Aviation and NTSB: a flight recorder plus mandatory incident reports, where a single finding becomes an airworthiness directive binding on every aircraft - an incident in one repo becomes a guardrail in all of them
- (idea by coach) Medicine: a repo has a chart - known allergies (what breaks it), chronic conditions (tech debt), past procedures (major refactors) - and you read the chart before operating
- (idea by coach) Law and precedent: decisions cite prior decisions, and a decision can be explicitly OVERRULED with a stated reason while the old one stays visible - this is the clean answer to memory that has become wrong
- (idea by coach) Accounting double-entry: every memory claim carries provenance and can be audited back to its source event
- (idea by coach) Library science: a controlled vocabulary for tags so the store stays queryable as it grows past the point where anyone remembers what they called things
- (idea by coach) Wikipedia: contested facts get flagged rather than silently overwritten, and memory needs a review mechanism once more than one agent writes to it
- (idea by coach) Kitchen mise en place: pre-warm the memory context for a feature during the planning phase so execution never stalls waiting on retrieval
- (idea by coach) Casino player tracking: compute expected value per area of the codebase and learn which regions reliably cost more than estimated
- (idea by coach) Sports film study reviews losses more than wins - consolidation should weight failures substantially higher than successes
- (idea by coach) Toyota production system: standard work is convention memory, the andon cord is the escalation path, and every kaizen is a memory write with a named owner
- (idea by coach) Actuarial tables price risk from history - route model tier and verification depth by the historical risk profile of the area being touched
- (idea by coach) Tradecraft compartmentalization: memory scoped by agent capability, so the executor never receives the entire project history it does not need
- (idea by coach) Jazz standards: a shared repertoire everyone knows is what makes improvisation fast - a library of known-good patterns per stack is the highest-leverage memory content
- (idea by coach) Chess opening books: precomputed known-good sequences for common positions, so common feature shapes (add a CRUD endpoint, add a migration, add a webhook) get a stored opening
- (idea by coach) Air traffic control flight strips: the compact record handed between controllers means the agent-to-agent handoff artifact is itself the memory unit
- (idea by coach) Changelogs and semver: memory of what changed and why, in a format humans already know how to read
- (technique) started Time Horizon Ladder
- (insight by coach) Stepping the memory layer through 1, 100, 1000 and 10000 features shows the dominant cost FLIPS from writing memory to invalidating it, which reverses what the design should optimize for
- (idea by coach) At one feature memory is pure overhead - v0 should contain NO memory layer at all, only the episodic event log, which is free and quietly becomes the substrate everything else is built from later
- (idea by coach) At roughly twenty features the decision ledger starts paying, and conventions memory should be built first because it has the highest hit rate, the smallest size and the cheapest retrieval
- (idea by coach) At roughly one hundred features naive load-all-memory breaks and real indexing plus ranking becomes mandatory, as does the consolidation job
- (idea by coach) At roughly one thousand features memory ROT dominates - most entries reference code that no longer exists - and decay, pruning and re-validation become the main engineering problem
- (idea by coach) At ten thousand features memory is a product with its own maintenance burden, so it must be mostly DERIVED and recomputable from git rather than stored, or the maintenance predator returns and wins
- (idea by coach) Across five repos patterns transfer, but across fifty the per-repo noise swamps cross-repo signal unless cross-repo memory stores only abstract patterns and never concrete snippets
- (idea by coach) What transfers between products is how-we-do-auth, never the auth code itself - this single rule determines the schema of cross-repo memory
- (idea by coach) What survives every rung of the ladder is the append-only event log and git itself, because both are immutable and always true
- (idea by coach) What breaks at every single rung is anything storing file paths, line numbers or code snippets
- (idea by coach) Design rule falling out of the ladder: memory stores questions and their durable answers plus pointers to stable anchors, never copies of code
- (idea by coach) Stable anchors ranked by durability: test names beat public API symbols beat module names beat file paths, and line numbers are never acceptable anchors
- (idea by coach) Hook memory invalidation to the refactor itself - the committer detects renames and rewrites anchors as part of the commit, so memory cannot drift behind the code
- (idea by coach) Periodic re-validation sweep samples memory entries and checks their anchors still resolve, flagging the dead ones instead of waiting to be misled by them
- (idea by coach) Make memory rebuildable: if ninety percent can be regenerated from git history plus the event log, then corruption stops being a crisis and the schema becomes free to change
- (idea by coach) At the ten-year rung the model has changed many times - memory as structured facts and tests survives that, memory as tuned prompt text does not
- (idea by coach) At the absurd far rung the memory becomes more valuable than the code, because code is regenerable while accumulated decisions and constraints are not - which inverts what you back up and what you version
- (idea by coach) The consolidation job is the ONLY genuinely new subsystem worth building for memory, because everything else is querying git and the event log
- (idea by coach) Measure memory ROI directly as retrieval token cost versus measured reduction in rework, and delete the memory layer outright if that number is not positive
- (insight by coach) SYNTHESIS: (1) Strongest signal is convergence - sleep consolidation in biology and write-ahead-log plus compaction in databases are the same design reached independently, both saying never write long-term memory during the run; log fast and lossy, consolidate afterward when outcomes are known and tokens are cheap. (2) Biggest scope cut: git already IS most of the memory store, so build nothing git log and git blame can answer, and require memory to be rebuildable from git plus the event log - memory becomes an index over things already held, making schema change free and corruption survivable. (3) Key reframe: memory that enforces itself costs zero tokens at read time - conventions become lint rules, failures become regression tests, incidents become guardrails, so the layer real job is CONVERTING memory into executable artifacts and falling back to retrieval only for the irreducibly fuzzy. (4) The trap from the horizon ladder is that dominant cost flips from writing memory at 100 features to INVALIDATING it at 1000, so decay policy at write time, durability-ranked anchors with line numbers banned, and invalidation hooked to the refactor commit must all be day-one decisions. (5) Two cheap unbuilt wins: memory as a ROUTING input (risk memory picks verification depth, cost memory picks model tier) and negative memory which is worth more per token than positive memory. (6) Cross-repo memory must store abstract patterns never snippets - how-we-do-auth, not auth code - and that single rule determines the schema. (7) v0 verdict agrees with session one: build no memory layer, keep only the episodic event log, which is simultaneously flight recorder, timeline, resume mechanism and the substrate for everything later. (8) Self-referential: the memlog pattern this session ran on - append-only, one line per idea, never edited, single consolidation pass at the end - IS the architecture to build.
