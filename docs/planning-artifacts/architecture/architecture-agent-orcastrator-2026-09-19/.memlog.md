- (version) Claude Agent SDK verified at code.claude.com/docs/en/agent-sdk - packages claude-agent-sdk (Python) and @anthropic-ai/claude-agent-sdk (TypeScript), PYTHON AND TYPESCRIPT ONLY; other languages must drive the claude CLI as a subprocess with -p and --output-format json
- (version) Agent SDK ships the Claude Code harness as a library: built-in Read/Write/Edit/Bash/Glob/Grep/WebSearch tools, agent loop, context management, hooks, subagents, permissions, sessions, MCP, skills/commands/memory loaded from .claude/, and plugins
- (constraint) DECISIVE - claude -p uses the subscription login ONLY when NOT in bare mode; the docs state plainly that bare mode does not use your subscription login and requires ANTHROPIC_API_KEY. Deep subscription-only constraint therefore forbids --bare and forbids the Messages API and Managed Agents paths entirely, both of which bill per token at API rates
- (constraint) SECURITY - without --bare, a -p session runs the hooks in a project .claude/settings.json and connects the servers in its .mcp.json even in a folder never trusted, with no workspace trust dialog and no per-server approval prompt; combined with the subscription constraint forcing non-bare, this is a supply-chain exposure the threat model does not currently cover
- (version) CLI gives typed agent output directly - --output-format json plus --json-schema returns the validated result in a structured_output field, which implements the agents-as-pure-functions-over-typed-files contract without custom parsing
- (version) CLI gives the event stream directly - --output-format stream-json emits newline-delimited events including system/init (model, tools, mcp servers, plugins), system/api_retry, permission_denied, and a final result message; subagent messages carry parent_tool_use_id so the full nesting tree is reconstructable for the timeline
- (version) CLI json output reports total_cost_usd and a per-model breakdown as client-side estimates, usable as a usage proxy even though the subscription is not billed per token
- (version) CLI supports sessions across directories - --resume takes a session id or an absolute transcript .jsonl path and finds the session in any project on the machine, which serves the pause-and-resume capability
- (version) CLI permission surface maps onto reversibility tiers - --permission-mode auto/dontAsk/acceptEdits, --allowedTools with permission rule syntax including prefix matching such as Bash(git diff *), and --permission-prompts none for genuinely unattended runs
- (version) CLI interruption semantics - SIGTERM exits 143 leaving the turn unfinished, SIGINT ends the turn, the SDK exposes interrupt(); background subagents hold the process open with a ten-minute idle ceiling configurable via CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS
- (constraint) LICENSING - Agent SDK docs state Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products without prior approval; this bounds Q5 replication, each additional person must run their own instance under their own Claude Code login rather than receiving a product wired to Deep subscription
- (note) Framing correction - MCP is not an agent-invocation mechanism and was wrongly listed as a third alternative; MCP is how the TOOL SERVERS expose their domains to agents, which is an orthogonal decision
- (decision) AD-1 CHOSEN BY DEEP - step agents are invoked as claude -p SUBPROCESSES, not via the in-process Claude Agent SDK. Binds every step agent and the engine. Prevents divergence where one unit embeds the SDK in-process while another shells out, producing two incompatible agent contracts, two permission surfaces and two failure models. Rule: the engine spawns one claude -p process per step, never in bare mode (subscription auth), passes the step contract via --json-schema and consumes --output-format stream-json; no unit may link the Agent SDK as a library. Rationale: a subprocess IS a stateless pure function enforced by the OS rather than by discipline, kill and fork controls become trivial, and the engine language stays open. Cost accepted: canUseTool and typed message objects are given up, permission plumbing is parsed from the JSON stream instead.
- (question) Engine implementation language still open - Deep answered the invocation question but not the language one; subprocess invocation deliberately leaves it unconstrained
- (direction) Deep answered that the web renderer is an ACTUAL CONTROL SURFACE, not a convenience view - clickable timeline, pause/inject/kill/fork, cost heat-map - which was the stated tiebreaker
- (version) Zod v4 verified at zod.dev/json-schema - native z.toJSONSchema() with no external dependency, targets draft-7 and draft-2020-12, options for unrepresentable/reused/cycles/io, explicitly used for AI structured outputs; the external zod-to-json-schema libraries are no longer actively maintained as of November 2025
- (note) Coach lean reversed - the earlier Python recommendation rested on the pydantic-to-JSON-Schema chain being unique to Python; Zod v4 provides the identical chain, so that argument does not survive
- (decision) AD-2 - the engine, the TUI and the web control surface are all written in TypeScript on Node. Binds every unit. Prevents a split where the engine and the renderers speak different languages and the step-contract schemas get defined twice, drifting apart. Rule: one TypeScript package owns engine, TUI and web; step contracts are Zod v4 schemas exported via z.toJSONSchema() and passed to claude -p --json-schema; no second implementation language is introduced for any unit in this contract. Rationale: identical schema chain to pydantic, NDJSON is the native runtime format and the entire CLI interface is NDJSON, one language spans all three surfaces, and Claude Code ecosystem is TypeScript-first. Cost accepted: Go stronger process supervision is given up.
- (decision) AD-3 - the web renderer is a first-class control surface, not a read-only view. Binds CAP-14 and CAP-15. Prevents the renderers diverging into a rich web app and a degraded terminal view, or the reverse. Rule: every steering action (pause, inject, kill, fork) is exposed by BOTH the TUI and the web app and is issued through the same command path into the engine; neither renderer may own a control the other lacks.
- (constraint) Ink is the TUI library (React for terminals; used by Gatsby, Parcel, Yarn, Terraform, Prisma, Shopify) - consistent with AD-2 since it keeps the TUI in the same language and component model as the web surface
- (direction) Deep answered jq-over-a-file for debugging a run six weeks later, which decides the event store shape
- (decision) AD-4 - the event log is append-only JSONL, one file per feature run, and it is the DURABLE TRUTH. Binds CAP-8, CAP-9, CAP-14, CAP-15, CAP-17, CAP-21 and every renderer. Prevents one unit treating a database as authoritative while another treats the file as authoritative, which would make replay, shadow mode and consolidation disagree about what happened. Rule: every event is appended as one JSON object on one line by the runtime recorder and never mutated; exactly one writer per file; any index or database is a DERIVED projection that must be reconstructable by replaying the files, and no component may read an index for a fact the log holds. Rationale: no write contention across concurrently running features since each owns its file, crash-safe by construction, inspectable with jq and tail at 2am, consistent with the git-and-plain-text grain of the rest of the system.
- (decision) AD-5 - a single event envelope is shared by every emitter. Binds all units that write or read events. Prevents each agent, tool server and engine phase inventing its own event shape, which would make one timeline unrenderable and break replay. Rule: every line carries ts (RFC3339 with milliseconds), seq (monotonic per file), feature, run, step, emitter, type, and payload; when the event originates from a claude -p stream the original parent_tool_use_id and session_id are preserved verbatim so the subagent nesting tree stays reconstructable; unknown types must be ignored by readers rather than treated as errors, so adding an event type is never a breaking change.
- (decision) AD-6 - the SQLite query index is DEFERRED to stage 3 and is optional even then. Binds the substrate stage. Prevents building a schema and a migration path before any query actually hurts. Rule: no SQLite until a concrete query in shadow mode or the trust record cannot be served acceptably by scanning JSONL; when added it is a pure projection per AD-4 and its loss is a non-event.
- (question) Where the JSONL event logs live on disk is unresolved and belongs to the operational-envelope decision - per-project inside the repo, or centrally under a user-level directory
- (direction) Deep answered that closing the laptop mid-feature must resume exactly where it was, which decides the supervision model in favour of a reconciler over on-disk state
- (decision) AD-7 - the engine is a RECONCILER over on-disk state, not a long-lived supervisor holding run state in memory. Binds the engine, every step agent, the worktree/container/resource lifecycle, CAP-5, CAP-6 and CAP-23. Prevents a split where one unit assumes an in-memory owner it can call into and another assumes durable state it can re-read, which would make crash recovery and the escape hatch behave differently depending on which unit was asked. Rule: each feature has exactly one state file that is the sole authority on its progress; the engine loop reads state, takes at most one next action, writes state, and holds no authoritative run state in memory; killing the engine at any instant and starting it again must produce identical behaviour to never having stopped; every reconciler action is idempotent. Rationale: instant disengage and the escape hatch become properties of the design rather than shutdown handlers that must be correct, the event log is already the durable truth under AD-4, and claude -p already owns resumable sessions by id so keeping them alive in memory duplicates state the CLI manages better.
- (decision) AD-8 - a step interrupted mid-flight is rejoined by session id when one was recorded, and otherwise re-run from its input file. Binds every step agent and the reconciler. Prevents one unit assuming resume semantics and another assuming re-run semantics, which would silently double-apply side effects or silently discard completed work. Rule: the feature state file records the claude session id as soon as the subprocess reports it; on recovery the reconciler attempts claude -p --resume with that id, and on failure re-runs the step from its typed input file; re-running is always safe because AD-1 makes every step a pure function over typed files, so no step may depend on having run exactly once.
- (constraint) State file writes are atomic - write to a temporary file in the same directory then rename, so a crash mid-write can never produce a partially written state file; readers never see a torn state
- (constraint) Reconciliation is concurrent across features but bounded by conflict domain per SPEC - the reconciler may advance several features in the same pass, and serializes only features whose declared file territories overlap
- (direction) Deep thinks in terms of runs rather than projects when reviewing what happened, which decides the operational envelope in favour of central state
- (decision) AD-9 - all orchestrator state is CENTRAL under a single root, never inside the target repository. Binds the engine, both renderers, the resource pool, the worktree lifecycle and CAP-19. Prevents one unit writing run state into the repo while another reads it centrally, and removes the worktree ambiguity where a worktree of a repo would contain a second copy of in-repo state with no rule for which is authoritative. Rule: the root is ORCH_HOME, defaulting to ~/.orch; runs live at runs/<run-id>/ holding events.jsonl and state.json, worktrees at worktrees/<run-id>/, leased resources at pool/, per-project registration and profile at projects/<project-id>/; nothing the orchestrator owns is ever written inside the target repository except the feature branch itself and git notes. Accepted cost: deleting a project directory orphans its state under the root, so a prune command is required.
- (decision) AD-10 - a project is identified by the SHA of its first commit, not by its filesystem path. Binds project registration, the profile lookup, memory scoping and every unit that resolves a repo to its configuration. Prevents one unit keying a project by path while another keys it by remote URL or directory name, which would silently split one project into several after a move or rename, scattering its history and profile. Rule: project-id is the first-commit SHA, recorded at registration; the filesystem path is a mutable pointer updated on mismatch; a repository with no commits cannot be registered until it has one.
- (decision) AD-11 - the executor container image is BUILT LOCALLY from a Dockerfile in this repository and tagged with the content hash of that Dockerfile; no image is pulled from a registry. Binds the isolation tiers and the threat model containment layer. Prevents one unit expecting a registry-pinned tag while another builds locally, giving two different sandboxes with different hardening. Rule: the image is rebuilt automatically when the Dockerfile hash changes and never otherwise; the build is the only step permitted network access outside the egress allowlist. Rationale: keeps the supply-chain surface at zero, consistent with the egress allowlist proxy already specified.
- (decision) AD-12 - distribution is clone-and-run, not a published package. Binds installation and the replication model in SPEC. Prevents shipping something that wires other people to Deep own Claude Code login, which the Agent SDK terms forbid without prior approval. Rule: each person clones the repository and runs it under their own Claude Code login; upgrade is git pull; no npm publish and no bundled credentials.
- (direction) Deep chose exploration for external domains, with the condition that what is explored informs and updates the other steps - resolved as record/replay rather than as a choice between exploration and determinism
- (decision) AD-13 - external domains are exposed to agents as one MCP server per domain, passed with --mcp-config, and every external READ is recorded. Binds every step agent, every tool server, CAP-3, CAP-7 and the re-run guarantee in AD-8. Prevents one unit exploring a domain live while another expects its inputs pre-resolved, which would make the same step non-deterministic across re-runs and make two runs of one feature disagree. Rule: each domain runs as exactly one MCP server holding that domain credential and no other; agents may explore it freely; the runtime records every request and response to the event log and to the run shared fetch record; on re-run the fetch record is served first and the domain is contacted only for a request not already recorded. Rationale: exploration buys genuinely better analysis, and record/replay restores the determinism that AD-8 re-run safety depends on, so neither has to be sacrificed.
- (decision) AD-14 - the run shared fetch record is readable by every later step in that run. Binds all step agents. Prevents each step re-fetching what an earlier step already pulled, and prevents two steps in one run seeing different versions of the same external record. Rule: a fetch recorded by any step is visible to every subsequent step of the same run and is served from the record rather than re-requested; within one run an external record has exactly one value.
- (decision) AD-15 - agents NEVER write to an external domain; they declare intended writes in their typed output and the engine executes them. Binds every step agent, the engine and the committer. Prevents a step performing a side effect that AD-8 would then double-apply on re-run, and prevents two units disagreeing about whether a declared write has already happened. Rule: a step output may contain declared write intents; the engine executes each exactly once against an idempotency key derived from run id plus intent id, records the outcome to the event log, and treats a repeated intent with a known key as already satisfied; no MCP server exposes a mutating tool to an agent.
- (direction) Deep chose a THICK profile that carries real project knowledge, accepting the duplication risk, because the system must work against repositories that do not document themselves
- (decision) AD-16 - the per-repo profile carries real project knowledge, and precedence between it and the repository own agent instructions is fixed. Binds CAP-20, the bootstrap agent, every step agent and the profile loader. Prevents the two-sources-of-truth failure where the profile and the repository CLAUDE.md or AGENTS.md disagree and different steps follow different guidance. Rule: the profile is authoritative for MECHANICS (test, lint, build and run commands, package manager, source layout, resource needs, risk tiers, conflict-domain hints); the repository own instructions are authoritative for CODE CONVENTIONS and are loaded automatically by non-bare claude -p; where both speak to the same point the repository wins and the profile entry is flagged stale rather than silently applied; profile knowledge sections are additive only and may never contradict the repository.
- (constraint) Every profile knowledge entry carries provenance and a decay policy in the same vocabulary as memory-design.md (permanent, until-refactor, N-features, session), and a re-validation sweep flags entries whose anchors no longer resolve - this is the agreed mitigation for the rot risk the thick profile accepts
- (constraint) The profile is authored by the bootstrap agent, reviewed by the user before first use, and stored centrally at projects/<project-id>/profile.toml per AD-9, never inside the target repository
- (constraint) CONVENTION ids - run id is a ULID so runs sort chronologically as strings; project-id is the first-commit SHA per AD-10; feature slugs are kebab-case; step ids are stable declared names, never positional indexes
- (constraint) CONVENTION time - all timestamps are RFC3339 with milliseconds in UTC, everywhere, including the event envelope and state files
- (constraint) CONVENTION errors - every failure crossing a unit boundary uses the shape code, message, retryable, cause; step agents emit it in their typed output and the engine emits it to the event log unchanged
- (constraint) CONVENTION event type names are dot-namespaced and past-tense, for example step.started, agent.tool_used, fetch.recorded, write.executed, permission.denied
- (constraint) CONVENTION formats - human-edited configuration is TOML, machine-owned state and events are JSON; every schema is defined once as a Zod v4 schema and exported with z.toJSONSchema() rather than hand-written
- (constraint) CONVENTION writers - only the reconciler writes a feature state.json, only the runtime recorder appends to its events.jsonl, and no unit writes diagnostics to stdout; everything observable goes to the event log
